# YouTube Playables readiness — separate from the standalone prototype

Reviewed against current official English documentation on **2026-09-24**. This is a readiness assessment, not a compliance certificate. No SDK was added, no portal account was accessed, and no submission or monetization eligibility was established.

## Verified requirements and remaining work

| Area | Verified official requirement | Prototype status / next action |
| --- | --- | --- |
| Bundle | Root `index.html`; portal upload in ZIP format. | Static `dist/` has the root entry. Package its contents, not its parent directory, after integrating the SDK. [Getting started](https://developers.google.com/youtube/gaming/playables/reference/getting_started), [Portal guide](https://developers.google.com/youtube/gaming/playables/developer_portal) |
| Size and paths | Initial transfer under 30 MiB (recommended under 15); total under 250 MiB; each file under 30 MiB (recommended under 512 KiB); at most 8,000 files; relative paths and restricted filename characters. | About 1.26 MB raw / 0.35 MB gzip, six bundle files (including dependency notices). Largest vendor file is about 1.21 MB raw, exceeding the **recommended** per-file size but below the mandatory limit. Re-measure ingested SDK build. [Stability requirements](https://developers.google.com/youtube/gaming/playables/certification/requirements_stability) |
| Browser/mobile | Support YouTube-supported browsers and Android/iOS YouTube apps; peak JS heap at most 512 MB; interactive loading should take under five seconds. | Chromium desktop/phone-emulation checks only. Still test Safari, Firefox, Edge, actual devices, WebViews, memory and loading under realistic networks. [Stability requirements](https://developers.google.com/youtube/gaming/playables/certification/requirements_stability) |
| Required SDK initialization | Load SDK before game code, call `firstFrameReady()` before `gameReady()`, and signal interactive readiness only once usable. | Still required. [SDK reference](https://developers.google.com/youtube/gaming/playables/reference/sdk) |
| Save and score | Use SDK storage for material progress, wait for successful `loadData()` before `saveData()`. Optional `sendScore()` must agree with saved best. | Browser best score currently uses localStorage. Replace the adapter with versioned SDK persistence, asynchronous load gating and error handling. [Integration requirements](https://developers.google.com/youtube/gaming/playables/certification/requirements_integration) |
| Pause/audio | Use SDK `onPause`/`onResume`, not browser visibility APIs, in Playables. Pause all execution/rendering; resume only when permitted. A Playables adapter must replace that source, gate resume, sleep/wake the engine, and add a host audio gate. Standalone pause currently freezes simulation/tweens/audio but does not stop Phaser's render loop. [Integration requirements](https://developers.google.com/youtube/gaming/playables/certification/requirements_integration) |
| Testing/certification | SDK integration requires the test suite; release review also covers design, accessibility, privacy, localization and trust/safety. | Local tests are not certification. Run official tests and portal-provided development links after real integration; supply metadata/thumbnails and review all policy categories. [Certification](https://developers.google.com/youtube/gaming/playables/certification/requirements) |
| Portal access | The public guide describes private preview, invitation-based participation and an onboarded channel with appropriate manager access. | User access has **not** been verified. Establish access before planning submission. [Portal guide](https://developers.google.com/youtube/gaming/playables/developer_portal) |
| Monetization | YouTube-provided ads functions are permitted with required pause/audio handling and portal monetization settings. Off-platform advertising, monetization and purchases are prohibited. | No ads/purchases implemented. Availability and commercial terms for this developer remain unverified; no revenue claim. Any future ads must use YouTube functions and current rules. [Monetization requirements](https://developers.google.com/youtube/gaming/playables/certification/requirements_monetization) |

The official pages' generated summaries lag some normative sections: the stability summary says 15 MB while the numbered requirement says **30 MiB mandatory / 15 MiB recommended**; the monetization summary says no advertising while the numbered requirement permits YouTube-provided ads. This checklist follows the numbered English requirements. The older portal guide also describes monetization rollout caveats, so account-specific availability needs confirmation.

## Working-title check

Searches for “Water Hole” plus “game” and “app store” surfaced an indexed Android game listing for **Water Hole**, package `com.redlinegames.waterhole2`, attributed to RedLineGames: [AppRecs listing](https://apprecs.com/android/com.redlinegames.waterhole2/water-hole), [Chrome-Stats listing](https://chrome-stats.com/d/com.redlinegames.waterhole2). Direct retrieval of these listing pages and the Play Store page was unavailable during this session, so current store availability is unverified. The same-name listing is enough reason to **retain Water Hole only as the requested prototype title and choose/check a distinct release name**. This was an obvious-conflict search, not trademark clearance.
